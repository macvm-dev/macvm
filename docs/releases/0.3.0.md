## 新功能

- **TCP 端口转发**：把 Mac 上的端口转发到客户机里的端口，Mac 上的程序经 `localhost` 就能连客户机里的服务。
  - App 里在虚拟机详情页的「端口转发」一节，或虚拟机窗口工具栏的端口转发按钮里添加、移除；虚拟机运行中改动也立即生效。
  - 默认只有这台 Mac 能连；添加时勾选「允许局域网里的其他设备连接」，网络里的其他设备也能连。
  - 命令行：`macvm create --forward`、`macvm set --add-forward` / `--remove-forward` 写进虚拟机配置，写法是 `[地址:]宿主端口:客户机端口`；`macvm forward <名> <转发>…` 做临时转发，不改配置，按 Ctrl-C 结束。
  - 客户机装了 MacVM 代理时，经代理连客户机的 `127.0.0.1`，只监听回环地址的服务也连得上。
  - 只转发 TCP。克隆或从模板新建的虚拟机不带原来的转发。

## 改进

- 操作出错的提示弹在你正在用的窗口里。以前只弹在资料库窗口，在虚拟机窗口里改端口转发、共享文件夹时出错（比如端口已被占用）会看不到。

## 移除

- **移除桥接网络与网络辅助程序 macvm-netd**。Wi-Fi 上桥接后宿主与客户机互相连不通，桥接还要常驻一个需要管理员权限的辅助程序。要从 Mac 或局域网访问客户机里的服务，改用端口转发。
  - 原来设成桥接的虚拟机照常开机，改用 NAT 网络，MAC 地址不变；客户机的 IP 会变成 NAT 网段里的地址。
  - `macvm create` / `macvm set` 不再接受 `--network`，App 设置里的「网络辅助程序」与详情页的网络选择也已去掉。
  - 以前装过的辅助程序不会自动注销，可以在「系统设置 › 通用 › 登录项与扩展」里关掉，或运行 `sudo launchctl bootout system/cn.barey.macvm.netd`。

## New

- **TCP port forwarding**: forward a port on your Mac to a port in the guest, so apps on the Mac can reach services in the guest through `localhost`.
  - In the app, add or remove forwards in the Port Forwarding section of a virtual machine's details, or from the new Port Forwarding button in the virtual machine window's toolbar. Changes take effect right away, even while the virtual machine is running.
  - By default only this Mac can connect; turn on "Allow other devices on the network to connect" when adding a forward to let them connect too.
  - Command line: `macvm create --forward` and `macvm set --add-forward` / `--remove-forward` save forwards in the configuration, written as `[address:]host-port:guest-port`; `macvm forward <name> <forward>…` forwards temporarily without changing the configuration until you press Ctrl-C.
  - When the MacVM agent is installed in the guest, connections go to the guest's `127.0.0.1` through the agent, so services listening only on loopback are reachable too.
  - TCP only. Clones and virtual machines created from templates don't carry over forwards.

## Improvements

- Error alerts now appear in the window you're working in. Previously they appeared only in the library window, so errors from changing port forwards or shared folders in a virtual machine window (such as a port already in use) could go unnoticed.

## Removed

- **Bridged networking and the macvm-netd network helper are removed.** On Wi-Fi, a bridged guest and the host couldn't reach each other, and bridging needed an always-running helper with administrator privileges. To reach services in the guest from the Mac or the local network, use port forwarding instead.
  - Virtual machines set to bridged still start, now on the NAT network with the same MAC address; the guest gets a new IP address on the NAT network.
  - `macvm create` / `macvm set` no longer accept `--network`, and the Network Helper setting and the network picker in the details are gone.
  - A previously installed helper isn't unregistered automatically. Turn it off in System Settings › General › Login Items & Extensions, or run `sudo launchctl bootout system/cn.barey.macvm.netd`.
