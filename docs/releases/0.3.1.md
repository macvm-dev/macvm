## 新功能

- **桥接网络**：使用 VZ 引擎的 Linux、macOS 虚拟机可在关机后，在详情页选择桥接到宿主网卡，让客户机从局域网路由器获取地址。无需安装网络辅助程序或管理员授权。

## 改进

- 桥接网络通过客户机代理查询 IP；在 Wi-Fi 上宿主与客户机无法直接互访时，仍可通过代理使用 `exec`、`ssh`、`cp` 和端口转发。

## 升级与使用说明

- 0.3.0 之前通过旧辅助程序设置的桥接配置仍按 NAT 运行，MAC 地址不变；需要桥接时，请在详情页重新选择。
- 桥接虚拟机需要安装并运行 MacVM 客户机代理，才能查询 IP、使用 SSH 和端口转发。
- 命令行启动桥接虚拟机请使用 App 包内的 `macvm start`（或指向它的符号链接）；前台 `macvm run` 不支持桥接。网络模式在 App 内设置。
- 桥接不支持 Windows 客户机或 QEMU 引擎。在 Wi-Fi 上，宿主与客户机之间仍可能无法直接互访。

---

## New

- **Bridged networking**: Linux and macOS virtual machines using the VZ engine can now bridge to a host network interface. Shut down the virtual machine and select the interface in its details to get an address from your local router. No network helper or administrator authorization is needed.

## Improvements

- Bridged networking uses the guest agent to discover the guest's IP address. Agent-based `exec`, `ssh`, `cp`, and port forwarding remain available when Wi-Fi prevents direct connections between the host and guest.

## Upgrade and usage notes

- Bridged configurations created with the old helper before 0.3.0 still use NAT with the same MAC address. Select bridged networking again in the details if needed.
- Install and run the MacVM guest agent in bridged guests to discover their IP address and use SSH and port forwarding.
- To start a bridged virtual machine from the command line, use `macvm start` from the app bundle, or a symbolic link to it. Foreground `macvm run` does not support bridging. Set the network mode in the app.
- Bridging is unavailable for Windows guests and the QEMU engine. On Wi-Fi, the host and guest may still be unable to reach each other directly.
